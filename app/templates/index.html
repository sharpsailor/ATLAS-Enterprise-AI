Atlas Enterprise AI

Ask questions about company documents. Every answer is grounded in the documents, cited, checked by guardrails, and shows the steps it took.

View code on GitHub ↗

What problem it solves

Company knowledge is scattered across policies and handbooks. A plain chatbot makes this worse: it invents answers, can't see your documents, and does whatever a clever prompt tells it to. Atlas answers only from uploaded documents, cites the passage behind each claim, refuses when the evidence isn't there, and sends risky requests to a human instead of acting on them.

What happens when you ask a question

  1. Input guardrailBlocks prompt injection and attempts to extract secrets.
  2. Sensitive-action checkDelete, export, send or policy changes go to a human approval queue. The model never sees them.
  3. MemoryEarlier turns load from Postgres, so follow-up questions work.
  4. RetrieveThe question becomes a vector, and Pinecone finds the closest passages this user is allowed to see.
  5. Relevance gateIf no passage is relevant enough, Atlas refuses instead of guessing.
  6. GenerateThe LLM answers from those passages only and cites them, like [1].
  7. Output guardrailWithholds any answer that looks like it leaks keys or passwords.

Every answer in the chat shows these steps, with the real numbers and timings from that request.

What happens when a document is uploaded

  1. Direct uploadThe browser sends the file straight to object storage using a short-lived signed URL.
  2. Sandboxed parsingPDF, DOCX and text are read in a separate process with memory and time limits.
  3. Chunk and embedThe text is split into overlapping 1200-character chunks, and each becomes a 1024-dimension vector.
  4. IndexThe vectors are stored in Pinecone with access-control metadata. The document is then marked ready.
